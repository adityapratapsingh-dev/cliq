## Step 2 — real users, real messaging, Cloudflare D1 (PR #3)

Branch `step2-real-users-and-d1` -> PR #3. `npm run build` clean (zero TS/ESLint
errors). 7 API routes build as dynamic handlers.

### Architecture (important)
- `src/lib/store/` has a `Store` interface with TWO implementations: `memory.ts`
  (in-process fallback) and `d1.ts` (Cloudflare D1 over HTTP REST).
  `src/lib/store/index.ts` `getStore()` picks D1 when
  `CLOUDFLARE_ACCOUNT_ID`/`CLOUDFLARE_DATABASE_ID`/`CLOUDFLARE_API_TOKEN` are all
  set, else memory. **Never 500s when the DB env vars are missing** — the app
  stays online and Settings shows an amber fallback notice.
- `src/lib/d1.ts` speaks the HTTP REST API (no bindings), so it works on Vercel
  Node serverless. `ensureTablesExist()` runs CREATE TABLE IF NOT EXISTS and is
  memoised per process; the SQL lives in BOTH `schema.sql` (canonical) and
  `src/lib/schema.ts` (runtime copy) — keep them in sync.
- Auth: PBKDF2-SHA256 (120k iters) via Web Crypto (no native deps, works on
  Node+Edge) in `src/lib/auth.ts`. Sessions are **stateless HMAC-signed tokens**
  (`src/lib/session.ts`) in an httpOnly cookie — no sessions table needed, which
  matters because serverless instances don't share memory.
- `Message.fromMe` is part of the type but computed per-viewer. Stores set it
  from their `viewerId`; the client also re-derives it via `decorateMessages()`
  in `api-client.ts` using a module-level `currentUserId` set by `api.me()`.

### Bugs found & fixed (do not regress)
- **PATCH /api/users wiped arrays.** Passing `{ interests: undefined }` into the
  store's spread cleared `interests`, and JSON then dropped the key entirely →
  other users' `interests` came back undefined → "Cannot read properties of
  undefined (reading 'filter')" crash on the Chats tab. Fixed by building the
  patch object key-by-key in the route AND ignoring undefined keys in both
  stores. UI also uses `(x.interests ?? [])` defensively.
- The two "failures" in the API smoke test were **curl cookie-jar artifacts**
  (a `-b`/`-c` jar created before login can keep an empty value). Logout and
  unread-count semantics were re-verified directly and are correct.
