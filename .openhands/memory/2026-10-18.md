### Root cause of the one type error
`src/types/cliq.ts` ended up with **two** `export interface CliqNote` blocks
(HEAD's `{text,emoji,updatedAt}` + main's `{text,emoji,createdAt}`). TS
declaration-merges them, so `updatedAt` became required and `POST /api/notes`
(which writes `createdAt`) failed `tsc`. Fix: delete the stale duplicate; keep
main's `createdAt` shape. Lesson: duplicate exported interfaces in the same
module silently merge instead of erroring — grep for the interface name after a
merge, not just conflict markers.

## FIXED (2026-10-18): Vercel "Deployment was blocked" resolved
Applied the git-author fix. Approach that worked cleanly this time (do NOT use
`git filter-branch` on the branch while `main` is an ancestor of it — the filter
rewrites main's signed commits too, stripping signatures and breaking the PR
diff/ancestry):

1. Back up: `git branch backup-pre-reauthor <sha>`.
2. Re-create the branch at the true base and re-apply the FINAL TREE as ONE
   owner-authored commit:
   ```sh
   git checkout -B engagement-social-mechanics origin/main
   git read-tree --reset -u <final-tree-sha>   # exact verified tree
   git -c user.name=adityapratapsingh-dev \
       -c user.email=pratapsinghaditya202@gmail.com commit -F msg.txt
   ```
   `git read-tree --reset -u <tree>` stages a whole tree in one step — perfect
   for "same content, new parent". Verify `git rev-parse HEAD^{tree}` equals the
   pre-change tree.
3. `git push --force-with-lease=engagement-social-mechanics:<old-remote-sha> origin engagement-social-mechanics`

Result: commit `d6734ba` (author = repo owner), PR #11 went `mergeable:true`
/ `mergeable_state: clean`, and Vercel flipped `pending` → **`success`
"Deployment has completed"**. Verified via
`GET /repos/{o}/{r}/commits/{sha}/status`.

Also: `filter-branch` rewrites any `--tag-name-filter cat` tags and leaves
`refs/original/*`; clean up with `git tag -d`, `git update-ref -d
refs/original/...`, and `git branch -D` the backups.
