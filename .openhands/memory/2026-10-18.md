## Merge `origin/main` into `engagement-social-mechanics` (PR #11)

Both branches independently built the same "Realistic UI/UX polish" feature set
(theme, 3-col shell, Cliq Notes, voice notes, global search, profile redesign).
The engagement branch was based on an OLDER `main`; `origin/main` had since
landed the polish PR (`7603d6c`, "feat-ui-polish"). So the merge was mostly
"same feature, two implementations".

### Resolution strategy: adopt main's canonical polish, keep HEAD's engagement additions
- **Adopt main**: `ContextRail.tsx` (right rail), `SearchDropdown.tsx` (global
  search), `CliqNotes.tsx` (self-contained, no `NoteComposer` export),
  `types.ts` `activeNote()`, `Shell.tsx` (3-col shell with compact user pill),
  `CliqApp.tsx` (3-col layout wiring), `CreateModal.tsx` (dropzone),
  `globals.css`, `theme.ts` (indigo tokens).
- **Delete HEAD's orphans**: `RightRail.tsx` + `GlobalSearch.tsx` (superseded by
  ContextRail/SearchDropdown; `git rm`). `TREND_TOPICS` lived only there.
- **Keep HEAD**: `FriendsTab.tsx` (voice impl + StoryNotesBar + GroupChats),
  `ProfileTab.tsx` (achievement badges in ProfileHeader + 3-col MediaGrid +
  UserListModal), `ChatPostsTab.tsx` (StoryNotesBar at top).
- **Rewrite**: `stories/StoryNotesBar.tsx` now composes `StoryBar` + `CliqNotes`
  (was duplicating both). Signature `StoryNotesBar({ onOpenProfile })`.

### Root cause of the one type error
`src/types/cliq.ts` ended up with **two** `export interface CliqNote` blocks
(HEAD's `{text,emoji,updatedAt}` + main's `{text,emoji,createdAt}`). TS
declaration-merges them, so `updatedAt` became required and `POST /api/notes`
(which writes `createdAt`) failed `tsc`. Fix: delete the stale duplicate; keep
main's `createdAt` shape. Lesson: duplicate exported interfaces in the same
module silently merge instead of erroring — grep for the interface name after a
merge, not just conflict markers.

### Vercel "Deployment was blocked" is NOT a code error
PR #11 shows `Vercel | failure | Deployment was blocked` on every agent commit
(also on the pre-merge `f2fe868`). Cause: Vercel's git-author gate — the
committer must be a Vercel team member. Every OTHER branch in this repo
(`feat-*`, `fix-*`, `deps-*`) deploys fine because their commits are authored by
the repo owner `adityapratapsingh-dev <pratapsinghaditya202@gmail.com>`; the
agent commits are `openhands <openhands@all-hands.dev>`. Fix = commit as the
owner (see `2026-10-17-vercel-git-author.md`). This does NOT block merging:
after pushing the merge commit, PR #11 went `mergeable: true`
(`mergeable_state: unstable` = the failing/blocked Vercel status only).
Verify a real fix with `GET /repos/{owner}/{repo}/commits/{sha}/status`.
