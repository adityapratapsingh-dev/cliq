## Video compression (PR #6, 2026-10-16)

`src/lib/video-compress.ts` compresses video in the browser via canvas +
MediaRecorder (720p / 30fps / ~1.8 Mbps). Real-time by nature, so clips >120s skip
compression; <6MB skip too; MAX_UPLOAD_BYTES=200MB is enforced. Every failure path
returns the original file so posting never blocks.

**Critical gotcha:** MediaRecorder WebM files and many Android clips have NO
duration in the header -> `video.duration === Infinity`. Must use the seek-to-end
workaround (`resolveDuration()`), or compression silently never runs.

Tests: `npm run test:media` (12 checks). Browser-verified: 1.68MB -> 0.51MB (70%
smaller), output playable, no console errors.

Storage math for a 25 GiB plan: 100MB videos -> ~256 posts; compressed (~12.9MB per
60s clip) -> ~1988 posts.

## Video quality presets (PR #7, 2026-10-16)

Compression is now selectable. Measured in headless Chromium against a 3.37 MB
1080p source clip (real module, not estimated):

  preset      res    bitrate   output   ratio   ~posts in 25 GiB
  high        1080p  3.5 Mbps  1.15 MB  0.341   ~1856
  balanced     720p  1.8 Mbps  0.62 MB  0.183   ~3456  (default)
  dataSaver    480p  0.9 Mbps  0.29 MB  0.085   ~7473

**Key insight: bitrate dominates file size, not resolution.** MediaRecorder
targets a bitrate, so size scales almost linearly with it; cutting resolution
helps less because the encoder spends its budget on remaining detail. Lower
videoBitsPerSecond first, resolution second.

API: `VIDEO_PRESETS`, `preset` option on compressVideo/uploadMedia, and
`suggestPreset(bytes, duration)` (large/long -> dataSaver, small/short -> high).
UI: 3-way picker in CreateModal, shown only once a video is attached.
Tests: `npm run test:media` -> 21 checks (includes the measured capacities above).

## Reels UI (PR #8, 2026-10-16)

`Videos` tab rebuilt as a real vertical Reels player. New files:
`src/components/reels/Reel.tsx` (player), `ReelCommentsSheet.tsx`, and
`VideosTab.tsx` rewritten as the snap-scroll container.

Key mechanics (browser-verified):
- Autoplay via `IntersectionObserver({ threshold: 0.65 })`; non-visible reels
  pause AND rewind so audio never overlaps. Exactly one `video` unpaused.
- Single tap = play/pause glyph; double tap = heart burst at tap point + like.
- Mobile full-bleed; `lg` shows a 9:16 phone frame (428x810 @1280px wide,
  aspect 0.528) with Previous/Next buttons outside it.
- Comments bottom sheet at `h-[60%]` does NOT pause the video.
- Progress bar is seekable (click + arrow keys).
- Share sheet now sends posts into DMs (link + preview + mediaUrl attached).

New in CliqProvider: `followingIds` / `toggleFollow` / `refreshFollowing`,
derived from the real friendships table (friends + outgoing), optimistic with
rollback. Powers the For You / Following feed toggle.

Gotchas:
- Mobile browsers require `muted` for autoplay — mute defaults to muted.
- Test timing: the heart burst animation only lives 900ms, so assert
  immediately after the double tap or you'll see 0 and think it's broken.
- On mobile viewport the desktop sidebar is hidden; drive tab switches via
  `nav button`, not `aside button`.

## Notification system (PR #9, 2026-10-16)

Real triggers + red dots + Activity Center + live banner toasts.

Key files:
- `src/lib/notify.ts` — `notify({userId, actorId, kind, postId, text})`. Never
  notifies the actor; swallows insert errors so the primary action still succeeds.
- `src/components/notifications/useNotificationCenter.ts` — SWR at 4s; tracks
  seen ids so history isn't re-announced; `markRead(id?)` is optimistic.
- `src/components/notifications/{NotificationCenter,ActivityPill,NotificationBanner}.tsx`
- `src/lib/browser-notify.ts` — Web Notifications wrapper (only fires when the tab
  is hidden, so it complements the in-app banner).

Store: `listNotifications` joins actor AND post (type/media_url/content) in one
query; `unreadCounts()` returns all three counters in ONE round-trip (it runs on a
4s poll, so N queries would multiply latency). `markNotificationRead(id, userId)`
is scoped by user_id so one account can't touch another's rows.

Nav red dots: `useNavBadges()` in Shell.tsx reads `counts`/`lastSeen`/`feedLatest`
from CliqProvider. feedLatest reuses the SAME SWR cache keys as the tabs
(`feedKey('video')` etc.) so freshness tracking costs zero extra requests.
`markTabSeen(tab)` runs in a CliqApp effect and persists to localStorage.

Gotchas / lessons:
- A patch script's `assert` is what catches a silent no-op. My first nav-badge
  patch asserted only on the LAST replacement, so the earlier ones silently did
  nothing and I shipped no badges. Assert on EVERY replacement.
- Banner/pill auto-dismiss after 4s. A single check after waiting will MISS it and
  look like a bug — poll continuously (setInterval) when asserting on them.
- Toggling the same reaction off must NOT notify (it previously did, creating
  duplicates). Notify only when `post.myReaction === reaction`.
