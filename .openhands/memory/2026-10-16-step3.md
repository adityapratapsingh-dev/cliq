## Video compression (PR #6, 2026-10-16)

`src/lib/video-compress.ts` compresses video in the browser via canvas +
MediaRecorder (720p / 30fps / ~1.8 Mbps). Real-time by nature, so clips >120s skip
compression; <6MB skip too; MAX_UPLOAD_BYTES=200MB is enforced. Every failure path
returns the original file so posting never blocks.

**Critical gotcha:** MediaRecorder WebM files and many Android clips have NO
duration in the header -> `video.duration === Infinity`. Must use the seek-to-end
workaround (`resolveDuration()`), or compression silently never runs.

Tests: `npm run test:media` (12 checks). Browser-verified: 1.68MB -> 0.51MB (70%
smaller), output playable, no console errors.

Storage math for a 25 GiB plan: 100MB videos -> ~256 posts; compressed (~12.9MB per
60s clip) -> ~1988 posts.

## Video quality presets (PR #7, 2026-10-16)

Compression is now selectable. Measured in headless Chromium against a 3.37 MB
1080p source clip (real module, not estimated):

  preset      res    bitrate   output   ratio   ~posts in 25 GiB
  high        1080p  3.5 Mbps  1.15 MB  0.341   ~1856
  balanced     720p  1.8 Mbps  0.62 MB  0.183   ~3456  (default)
  dataSaver    480p  0.9 Mbps  0.29 MB  0.085   ~7473

**Key insight: bitrate dominates file size, not resolution.** MediaRecorder
targets a bitrate, so size scales almost linearly with it; cutting resolution
helps less because the encoder spends its budget on remaining detail. Lower
videoBitsPerSecond first, resolution second.

API: `VIDEO_PRESETS`, `preset` option on compressVideo/uploadMedia, and
`suggestPreset(bytes, duration)` (large/long -> dataSaver, small/short -> high).
UI: 3-way picker in CreateModal, shown only once a video is attached.
Tests: `npm run test:media` -> 21 checks (includes the measured capacities above).
