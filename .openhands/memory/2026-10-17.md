## Dependency warning fixes (follow-up to PR #1)

PR #1 got merged (auto-merged) before a follow-up commit landed, so the deps fix
went into a **new** branch `deps-security-patch` off `main` => **PR #2**.
Lesson: after pushing to a PR branch, verify the PR is still open/mergeable
before assuming later commits land in it.

Versions that matter (npm registry, this date):
- `next@15.5.4` (what create-next-app@15.5.4 shipped) — CRITICAL RCE
  CVE-2025-66478 / CVE-2025-55182, and npm-deprecated.
- Patched: 15.0.5, 15.1.9, 15.2.6, 15.3.6, 15.4.8, 15.5.7, 16.0.7 — **but
  15.5.7 and 16.0.7 are ALSO deprecated** by a second advisory
  (security-update-2025-12-11, CVE-2025-55184 DoS / 55183 source exposure).
  Current non-deprecated patched: **`next@15.5.28`** (15.x backport dist-tag) and
  `next@16.4.2` (latest). React fix line: 19.1.2 / 19.2.1.
- Chose 15.5.28 (stay in major 15) over 16.x to avoid a major migration.
- `next` pins `postcss` to exactly `8.4.31` (4 advisories). Fix with a
  package.json `overrides: { postcss: "^8.5.30" }` — works, drops audit 7->5.
- `allowScripts: { "sharp@0.34.5": true, "unrs-resolver@1.12.2": true }` in
  package.json silences the npm 11 "install scripts not yet covered by
  allowScripts" warning. Both are official next / eslint-config-next deps.
- Remaining 5 audit entries are dev-only: eslint-config-next -> fast-glob ->
  micromatch -> braces. `braces` has NO patched release. Not fixable.
- **ESLint: stay on ^9.** ALL 9.x is npm-deprecated (EOL), but ESLint 10 is not
  usable: eslint-plugin-import(2.32.0)/react(7.37.5)/jsx-a11y(6.10.2) cap peers
  at `^9`, so ESLint 10 makes npm report the tree **invalid**
  (`npm error invalid: eslint@10.12.0`). eslint-config-next@16 ships a native
  flat config (`eslint-config-next/core-web-vitals`, `/typescript` are arrays)
  and drops @eslint/eslintrc — it DOES run under ESLint 10 (surfaced a real
  `react-hooks/set-state-in-effect` error), but the invalid peer tree is worse
  than the deprecation notice. Revisit when those plugins support ESLint 10.
- `git cherry-pick --continue` failed here: no git identity in the repo AND
  core.editor=codespaces `code --wait` (not installed). Use
  `-c user.name=... -c user.email=...` and `commit -F <file>` instead.
